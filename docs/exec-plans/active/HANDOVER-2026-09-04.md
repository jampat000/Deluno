## Start here: the one task

**[#424](https://github.com/jampat000/Deluno/issues/424) — the Add screen does
not show that you already have a title.** The product owner asked for it twice,
in these words: *"if a user goes to add something they already have it should
show them they have it, just like Radarr does."*

Everything else on the list can wait behind it.

### What is already true, so you do not redo it

Adding something already held is **already a no-op**, and a duplicate is
**already impossible** at the database level:

```sql
ix_movie_entries_imdb_id              UNIQUE (imdb_id) WHERE NOT NULL
ix_movie_entries_metadata_provider_id UNIQUE (metadata_provider, metadata_provider_id)
ix_movie_entries_title_year           UNIQUE (lower(title), COALESCE(release_year, -1))
```

`series_entries` carries the same three. `SqliteMediaStateRepository.FindEntryIdAsync`
returns the existing row rather than creating a second one, matching on an IMDb
id, a provider and its id, or a title and year — and, since #423, a title
arriving *without* a year against one that has one.

**So the data is safe. What is missing is the telling.**

### What the screen does today

`apps/web/src/components/app/library-create-dialog.tsx` renders each metadata
result as poster, title, year, provider, rating, and either "Click to select" or
"Selected". The component has no concept of the library at all — it receives
`metadataResults` and a selection callback.

### Where the answer belongs

**On the server.** `apps/web/src/components/app/library-view.tsx` holds only the
current *page* of the catalogue, so a film the owner has but that is not on
screen would be reported as new. The client cannot answer this reliably and
should not try.

`FindEntryIdAsync` already answers exactly this question.

### What finishing it looks like

- `/api/metadata/search` results carry an "already held" marker **and the
  existing entry's id**, so the card can offer to open the title instead
- the Add dialog renders it plainly — the card marked, and a route to the title
  rather than a second add
- **the same for shows, not only films.** The owner said this explicitly:
  *"whatever we do with the delete route needs to be replicated for tv and same
  with the testing"*, and it applies to everything

*a check that validates something adjacent to the thing that matters*. Path
diagnostics reported the parent folder's writability under `Writable`; the
category check confirmed a name and never a destination; SABnzbd's health test
probed an endpoint that did not need the credential being tested. When you fix
one of those, ask where else that shape lives.

**Three times today the code was right and the request was wrong.** Each cost a
few minutes and would have cost a day as a false bug report:

- assumed `DELETE /api/movies/{id}` existed — it did not, removal went through
  `POST /api/movies/bulk` (now fixed, but the assumption came first)
- sent `"year"` where the contract says `"releaseYear"`, so the year was dropped
  and the dedupe had nothing to match on — reported as "dedupe is broken", which
  it was not
- grepped `.tsx` under `apps/web/src` for route coverage and concluded the
  inventory tool was wrong; the hits were app source, not tests

**And one design that had to be deleted rather than debugged:** an IMDb-matching
branch in duplicate detection, because `movie_entries.imdb_id` is `UNIQUE` and
two rows cannot share one. It was looking for something the schema forbids.

## Tools worth knowing about

- **`tests/Deluno.Persistence.Tests/Support/ApplicationTestHost.cs`** — boots the
  whole application over HTTP the way the hosts do, signed in as the owner, one
  line. Built today; it is what makes the 205 untested routes cheap. Schema
  initialisers run, pollers do not.
- **`scripts/coverage-inventory.mjs`** / `npm run coverage:inventory` — every API
  route and screen, and whether anything tests it. `--check` exits non-zero when
  anything is untouched. **Read the untouched number, not the covered one**: a
  route counts as covered when its path appears in a test, which over-counts.
- **`apps/web/src/layouts/app-layout-controls.test.tsx`** — holds every labelled
  button in the app to having a way to be pressed. Written after the
  notifications bell shipped with no `onClick`. The coverage inventory counts
  routes and screens, **not controls**, and was blind to it by construction.
